보안 전문가로서 아래 질문을 검토하라
- 특정 공격이 발생할 가능성은 얼마나 됩니까?
- 공격이 발생하면 최악의 결과는 무엇입니까?


최소 권한 원칙([_The Principle of Least Privilege_](https://en.wikipedia.org/wiki/Principle_of_least_privilege))
- 시스템 내의 각 부분에는 해당 작업을 달성하는 데에 필요한 가장 낮은 권한만 부여해야 한다
- 인간 개인이나 그룹뿐만 아니라 데이터를 읽거나 쓰거나 수정할 수 있는 모든 개체(머신, 라우터, 방화벽 포함)에 적용된다

제로 트러스트 보안 모델
- JITA(Just in Time Access)
- JEA(Just Enough Access)
- 데이터를 보호하기 위한 토큰화 및 암호화; 정책이 항상 목적에 적합하도록 보장하는 동적(또는 적응형) 액세스 제어 정책 적절한 세분성 수준으로 액세스를 제한하기 위한 마이크로 세분화.

보안 모델
- 보안 모델은 정보 시스템에서 보안 제어를 구현하는 데 사용되는 스키마 유형
- 특정 제어를 지정하는 경우는 거의 없지만 이론적 프레임워크를 제시하고 경우에 따라 여러 가지 다른 상황에서 구현할 수 있는 일련의 규칙을 제시

기밀성을 주로 다루는 보안 모델
Bell-LaPadula 모델
- 여러 보안 수준(예: 미분류, 기밀, 비밀 및 일급 비밀)이 있는 시스템에서 액세스 제어를 시행하는데 사용
Brewer와 Nash 모델
- 기밀을 유지하기 위해 액세스 제어를 시행하는 데 사용되지만 이해 상충을 최소화하려는 구체적인 목표가 존재
- 데이터 분리 및 동적 액세스 제어 사용

무결성을 다루는 일부 보안 모델
- Biba 모델
	- 액세스 제어 시행하는 데에도 사용
	- 개인과 정보에 서로 다른 무결성 수준이 할당된 경우 정보의 무결성을 보호하도록 설계

SBOM
- 소프트웨어에 포함된 모든 구성 요소, 라이브러리, 오픈소스 및 이들 간의 의존 관계를 상세히 기록한 **소프트웨어 자재 명세서**
- 이를 활용해서 애플리케이션 구축 프로세스에서 종속성을 자동으로 추적하면 공급망 변조를 평가하는데 큰 도움이 됨
- 소프트웨어 종속성 식별 > SBOM 생성 > 암호화 검증 가능한 방식으로 컨테이너와 SBOM 함께 패키징 > 프로덕션 로드 전에 컨테이너의 SBOM서명 확인 가능


핫 백업
- 정기적으로, 예약에 따라 수행하거나, 변경 사항이나 특정 조건에 따라 실행될 수 있습니다. 어느 쪽이든 시스템이나 파일의 현재 상태에 대한 백업이 생성
콜드 백업
- 데이터 일관성 측면에서 더 안전하지만 시스템 가동 중지 시간이 필요하므로 풀타임 가용성이 필요한 시스템에는 심각한 단점이 될 수 있습니다.

- 정보가 일시적으로만 사용되고 해독하고 싶지 않은 일부 데이터 유형도 고려해야 함(TLS)
